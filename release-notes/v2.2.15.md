# TankAlarm v2.2.15 — Server web UI: dead controls, lossless config round-trips, calibration identity, operator status

Server-only release. Client and Viewer are version bumps only; the notefile schema
(`_sv` 1), the command formats and the config payload the client parses are unchanged, so
v2.2.14 clients and viewers work with a v2.2.15 server without being reflashed.

Pull requests #314, #315, #316 and #317 (merged 2026-09-15). Details, verification and the
review history are in `CODE REVIEW/CODE_REVIEW_09152026_WEBSITE_PRS_314_317_CLAUDE.md`.

## Fixed

- **Six page controls did nothing but throw `ReferenceError`.** Expect Update and Remove
  Client on Site Config, Reset and the sensor-name link on Calibration, Cancel on the
  Transmission Log, and the custom date range on History called handlers that were local to
  the page's async IIFE. Every control that carries a client UID (those six plus the
  dashboard's Update / Snooze / Clear Relay / Remove Client, the client console's Edit
  Config / Approve Deletion and the config generator's cloud picker) is now bound through
  HTML-escaped `data-*` attributes and delegated listeners instead of inline JavaScript.
- **Config generator round-trips changed the configuration.** Loading and re-saving turned an
  ultrasonic sensor into a pressure sensor, added a 100/20 threshold to one-sided alarms and
  flipped a float switch's trigger; `alarmSms` was always emitted as `true`. All four
  round-trip now (new **SMS Alerts** checkbox in the alarm section), Sample Minutes is capped
  at 1092 and momentary relay durations at 65535 (the client's `uint16_t` fields), and a
  configuration is capped at 8 sensors (the client's `MAX_MONITORS`).
- **Calibration used the wrong sensor identity.** Keys were split at the first colon, so
  `dev:<imei>:1` submitted `clientUid:"dev"`. Keys split at the last colon, a verified level
  of 0 in (the empty-tank anchor) is accepted, blank fields are no longer submitted as 0,
  sensor index 0 is rejected (indexes are 1-based), and `POST`/`DELETE /api/calibration`
  resolve the client/sensor pair before touching the calibration log.
- **Operator status was misleading.** Float switches now read ON/OFF instead of "Tank Level
  --"; a level of exactly 0 in is a value; an "Update requested" pill expires after the
  client's reply window and offers Retry Update; `/api/clients` keeps the alarming sensor's
  alarm type; Site Config shows current-loop faults and mA; the outdated-client count uses a
  real version comparison; the Client Console deletion no longer prompts for a PIN the
  server ignores.
- **Logs and feedback.** Transmission Log filters are built from the emitted vocabulary
  (`error`, `ota`, `alarm`, `applied`, … were unreachable) and the CSV export matches the
  table; Contacts and Server Settings report `saved:false` as an error; route alias / FTP
  user / FTP password are rejected above 31 characters instead of truncated; `GET
  /api/location` URL-decodes the client parameter; login shows the lockout countdown; the
  config generator starts a new configuration for an unknown UID and refuses to guess the
  daily report time before the contacts directory has loaded; Server Settings loads once.
- **Style.** One header on every page, defined tokens, ~45 previously unstyled classes, a
  toast that is actually hidden, wrapping tooltips, tables that scroll on phones, contacts as
  a real table and one boxed checkbox vocabulary site-wide.

## Hardened

- Client UIDs are restricted to `dev:` followed by letters, digits, `:`, `_`, `-`, `.` at every
  ingestion and storage point (telemetry, alarms, daily, unload, serial logs, metadata,
  config snapshots, calibration), records persisted before the rule are validated when they
  load at boot, every page escapes quotes in attributes, and rejected UIDs are logged through
  a sanitising printer. Real Blues device UIDs (IMEI or hex) pass unchanged.

## CI

- New `check-web-pages` job: extracts every embedded page, runs `node --check` on each
  script block, and asserts that every inline handler call resolves at load time (60-case
  self-test). `build-firmware` depends on it, and pull requests against any base branch now
  run CI.

## Known / deferred

- Clear Relay sends the sensor's position in the dashboard array rather than its configured

- Client-side `uint16_t` parsing of `sampleSeconds` and `relayMomentaryDurations` is
  unchanged (the server now stays within those limits).
